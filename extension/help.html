Using Canvas Local Archive

Back to your courses · Browser capability check

Install and update

The project includes a signed local CRX and a Nix resolver for normal installation with an { id; hash; } entry. Apply the prepared integration in your own configuration, then restart Helium. No Developer mode or Load unpacked is needed for the packaged installation. For package updates, bump the manifest version, package with the same private signing key, update the hash, rebuild your configuration, and restart Helium. See docs/PACKAGED-INSTALL.md in the project.

For development, open helium://extensions, enable Developer mode, click Load unpacked, and choose the source extension folder. Update that installation with Reload on its extension card. In the toolbar’s Extensions menu, pin Canvas Local Archive; its icon opens the archive in the side panel. Packaged and unpacked installations have separate identities and browser storage; choose course folders again when switching. Existing course files/checksum indexes remain usable.

Connect and sync

Sign in to Canvas in this Helium profile; the panel connects by itself, and reconnects once a Canvas tab finishes loading. Authentication is checked using Canvas API data. A hostname or sign-in page is never accepted as proof.

Tap Set up on a course and pick its folder. The folder is the course root. Auto-sync turns on and everything available downloads. After that, auto-sync courses are synced when the panel opens and every 30 minutes while it is open (change this under Advanced → ⚙). Each sync rescans the course and downloads only missing or changed files; new uploads are included automatically. Only files are downloaded: pages and assignment descriptions stay on Canvas, but files attached to them are saved next to them. Untick files to exclude them. Files you edited are never overwritten.

Advanced mode adds Rescan, Check folder, Review before downloading, reports, the Python index import, and the activity log.

Review the actual folders

Check destination inspects all discovered relative paths; Review selected items inspects the selected set and current remote metadata. Existing unindexed files and local edits are preserved by default. Verify contents compares against the current remote material. Replace this file explicitly allows an overwrite. Missing files are downloaded; verified unchanged files are skipped.

If a selected page depends on a deselected attachment, the review lists that dependency. Saved HTML keeps its online link. Files found in several modules retain those associations and may have a copy in each selected module, without an additional Other course files copy.

Reports and recovery

Keep the side panel open during jobs. Cancel retains completed files and aborts open writers. Each course run saves a report under .canvas-archive/reports/; the checksum index is .canvas-archive/index.json. View latest report under Python index and reports. If saving the report fails, it remains in browser storage and Save report again retries the folder write.

After a closed tab, crash, or permission loss, reconnect, renew folder access, restore the last selection, and recheck. Recovery verifies actual disk contents. A newly-created empty placeholder can remain after interruption; it is unverified and requires explicit verification or replacement. The extension never deletes your notes or old materials.

Limits and troubleshooting

Only accessible course materials are archived. External sites and tools remain links. Quiz questions, submissions, replies, grades, and personal account files are outside the scan. A denied Files endpoint does not stop accessible module discovery; coverage limitations are reported.

Signed file hosting URLs may require additional HTTPS host access or may fail because of CORS. Grant only the file’s actual hosting origin; this does not change the Canvas API origin. If folder picking fails, run the capability check in your normal visible tab. Browser policies or the Linux desktop portal may prevent folder access. The only native helper is the optional LibreOffice PDF converter.

See the project’s README.md and docs/VERIFICATION.md for complete installation, development, testing, and known limitations.
